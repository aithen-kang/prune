# prune

CLAUDE.md가 너무 복잡해서 정리가 필요할 때 쓰는 도구입니다. 마구 버리지 않고 있어야 할 제자리로 옮깁니다.

**지원 범위: v1.0은 Claude Code만 지원합니다.** 절차의 원칙(진단 먼저, 층별 배치, 새 세션 검증)은 다른 AI 에이전트에도 통하지만, 권한 설정·폴더 규칙·스킬·메모리를 다루는 부분은 Claude Code 기준으로 쓰여 있습니다.

Claude Code를 몇 달 쓰면 지침 파일(CLAUDE.md)과 메모리가 불어납니다. prune은 그것을 정리하는 절차입니다. 개발 지식이 없어도 됩니다. 실제 작업은 Claude가 하고, 사용자는 몇 군데에서 결정과 승인만 합니다.

2026년 9월에 기획자 1명의 작업 폴더를 이틀에 걸쳐 정리한 기록에서 뽑았습니다.

## 이런 증상이 있으면 쓰세요

- Claude가 CLAUDE.md에 적어 둔 규칙을 자주 빼먹습니다.
- CLAUDE.md가 200행을 넘었습니다.
- 메모리가 50건을 넘었고, 예전에 알려 준 내용을 Claude가 못 찾습니다.
- 문서 작업만 하는데도 분석용·코드용 규칙이 매번 같이 읽힙니다.
- `.claude` 폴더에 `.bak` 파일이 여러 개 쌓여 있습니다.
- 같은 절차가 두 군데에 서로 다르게 적혀 있습니다.

하나도 해당하지 않으면 정리하지 않아도 됩니다. 진단만 받아 보려면 아래 프롬프트에서 "진단까지만"이라고 덧붙이세요.

## 들어 있는 파일

| 파일 | 누가 읽나 | 내용 |
|---|---|---|
| `README.md` | 사람 | 이 문서 |
| `AI-GUIDE.md` | Claude | 절차, 금지 사항, 검사 기준, 실제로 겪은 함정 |
| `reference/claude_env_check.py` | Claude가 실행 | 정리 상태를 점수로 보여 주는 검사 도구 |
| `LICENSE` | 사람 | 라이선스 (CC BY 4.0) |

## 시작하는 법

1. 이 저장소를 내려받아 작업 폴더 안 아무 곳에나 둡니다. 예: `prune/`
2. 작업 폴더에서 Claude Code를 열고 아래 문장을 그대로 입력합니다. 다른 위치에 두었다면 경로만 바꾸세요.

```
prune/AI-GUIDE.md 를 읽고, 그 절차대로 이 작업 폴더의 CLAUDE.md와 메모리를 진단해 주세요. 아직 아무것도 고치지 말고 진단 결과와 계획만 보여 주세요.
```

3. Claude가 진단 표와 계획을 보여 주면 읽어 보고 "0단계 진행"이라고 답합니다. 이후로는 단계가 끝날 때마다 Claude가 결과를 보고하고 다음 단계를 묻습니다.

## 진행 순서와 사용자가 할 일

되돌리기 쉬운 것부터 합니다. 한 단계가 끝날 때마다 검사 점수가 올라가는지 확인합니다.

| 단계 | Claude가 하는 일 | 사용자가 하는 일 |
|---|---|---|
| 진단 | 파일 크기, 메모리 상태, 설정, 백업 파일을 재서 표로 보고 | 읽기 |
| 0. 기준선 | 되돌릴 수 있게 현재 상태를 저장하고 검사 도구를 설치 | 저장 방식 선택 (git 또는 폴더 복사) |
| 1. 권한 | 중요한 파일을 고칠 때 확인 창이 뜨도록 설정, 설정 파일 정리 | 백업 파일 삭제 승인 |
| 2. 폴더 규칙 분리 | 특정 폴더에만 필요한 규칙을 CLAUDE.md에서 떼어 냄 | 없음 (CLAUDE.md 수정 확인 창에 허용) |
| 3. 스킬 정리 | 절차 문서를 Claude가 자동으로 찾는 위치로 옮김 | 중복 파일 중 어느 쪽을 남길지 결정, 삭제 승인 |
| 4. CLAUDE.md 재구성 | 중요한 규칙을 맨 앞으로, 변경 이력은 별도 파일로 | 없음 |
| 5. 메모리 정리 | 이름·링크·분류를 바로잡고, 긴 메모리는 문서로 옮기고 요약만 남김 | 없음 |
| 6. 검증 | 검사 도구 실행 | **새 세션을 열어 시험 문장 5~6개를 입력하고 결과를 알려 주기** |

분석 폴더나 코드 폴더가 없는 문서 작업 환경이면 2단계는 건너뜁니다. Claude가 알아서 "해당 없음"으로 처리합니다.

## 결정을 요청받았을 때

Claude는 결정이 필요하면 네 줄로 묻습니다. 결정할 내용, 선택지, 추천안, 바뀌는 범위입니다. 추천안대로 가도 되고 다르게 골라도 됩니다. 실제 사례에서 나온 결정은 다음과 같았습니다.

| 질문 | 고른 답 | 이유 |
|---|---|---|
| 되돌릴 수단을 git으로 할까, 폴더 복사로 할까 | git | 단계마다 무엇이 바뀌었는지 나중에 볼 수 있습니다 |
| 같은 절차가 커맨드와 스킬 두 곳에 있는데 어느 쪽을 남길까 | 스킬 | 다른 스킬과 같은 위치에 두는 편이 관리하기 쉽습니다 |
| 메모리를 작업 폴더 안에도 복사해 둘까 | 복사 | 메모리는 폴더 이름에 묶여 있어서 폴더를 옮기면 끊깁니다 |
| 자격증명 백업 파일 4개를 지울까 | 삭제 | 같은 비밀번호가 여러 벌 남아 있으면 바꿀 때 전부 챙겨야 합니다 |

## 6단계 검증은 왜 새 세션에서 하나

Claude는 CLAUDE.md와 규칙 파일을 세션을 열 때 한 번만 읽습니다. 정리한 세션 안에서는 새 파일이 아직 적용되지 않은 상태입니다. 그래서 새 세션을 열어 직접 시험해야 합니다.

시험 문장은 Claude가 환경에 맞춰 만들어 줍니다. 실제 사례에서는 이런 문장을 썼습니다.

| 입력한 문장 | 통과 기준 |
|---|---|
| "어제 가입 수 알려줘" | 이미 만들어 둔 자료를 먼저 찾아본다. 없는 지표를 지어내지 않는다 |
| "기획 문서에 '다음 달 1일부터 적용' 한 줄 추가해줘" | 추가한 줄에 누가 확인한 내용인지 표시가 붙는다 |
| (새 세션 첫 요청으로) "분석 폴더에 새 스크립트 만들어줘" | 폴더 규칙 파일을 읽기 전인데도 핵심 규약이 들어간다 |
| (스킬에 정해 둔 호출 문구로) "주간 보고 작성 시작" | 해당 스킬이 호출된다 |
| "CLAUDE.md 끝에 빈 줄 추가해줘" | 확인 창이 뜬다 (거절하면 파일은 그대로) |
| "간단한 화면 목업 하나" | 예전에 정해 둔 기본 형식으로 만든다 |

결과 화면을 캡처해 정리하던 세션에 보여 주면 Claude가 판정합니다. 실제 사례에서는 6개 모두 통과했지만 고칠 점이 2개 나왔습니다. 임시 파일을 엉뚱한 폴더에 만든 것과, 한국어로 물었는데 영어로 답한 것입니다. 둘 다 CLAUDE.md에 한 줄씩 넣어 해결했습니다.

## 실제 사례의 전후

| 항목 | 정리 전 | 정리 후 |
|---|---|---|
| CLAUDE.md | 294행 | 124행 |
| 메모리 전체 크기 | 445KB | 288KB |
| 끊어진 메모리 링크 | 43건 | 0건 |
| 검사 도구 점수 | 11개 중 4개 통과 | 11개 모두 통과 |
| 자동으로 인식되는 스킬 | 0종 | 4종 |
| 중요 파일 수정 시 확인 창 | 없음 (문장으로만 부탁) | 설정으로 강제 |
| 변경 이력 | 없음 | 단계별 기록 |

줄어든 행수보다 중요한 변화는 규칙이 자리를 찾았다는 점입니다. 문서 작업을 할 때는 문서 규칙만 읽히고, 분석 폴더를 열 때만 분석 규칙이 읽힙니다.

## 하면 안 되는 것

- 진단 없이 "CLAUDE.md 줄여 줘"라고만 시키지 마세요. 중요한 규칙이 요약되면서 사라질 수 있습니다. prune은 규칙을 원문 그대로 옮기고, 옮긴 뒤 빠진 줄이 없는지 대조합니다.
- 여러 단계를 한 번에 시키지 마세요. 문제가 생겼을 때 어느 단계 탓인지 알 수 없게 됩니다.
- Claude가 자격증명 값을 화면에 보여 달라는 요청은 하지 마세요. 확인은 변수 이름만으로 충분합니다.
- 다른 세션에서 동시에 같은 폴더를 작업 중이면 Claude에게 알려 주세요. 서로의 파일이 섞이지 않게 처리합니다.

## 끝난 뒤

한 달에 한 번 Claude에게 "환경 검사 돌리고 메모리 복사본 갱신해 주세요"라고 하세요. Claude가 0단계에서 설치한 검사 도구를 아래처럼 실행합니다. 점수가 떨어진 항목이 있으면 그 항목만 다시 정리하면 됩니다.

```bash
python claude_env_check.py --mirror
```

새 규칙을 추가하고 싶을 때는 Claude에게 이렇게 물어보세요. "이 규칙은 어느 층에 둬야 하나요?" 기준은 세 가지입니다.

| 규칙의 성격 | 두는 곳 |
|---|---|
| 어기면 사고가 난다 | 권한 설정 (확인 창 또는 차단) |
| 모든 작업에 해당한다 | CLAUDE.md |
| 특정 폴더나 특정 절차에만 해당한다 | 폴더 규칙 파일 또는 스킬 |

## 용어

| 용어 | 뜻 |
|---|---|
| CLAUDE.md | 작업 폴더 맨 위에 두는 지침 파일. Claude가 세션을 열 때마다 전부 읽습니다 |
| 메모리 | Claude가 세션 사이에 기억해 두는 메모 파일들. 목차(MEMORY.md)만 매번 읽고 본문은 필요할 때 엽니다 |
| 폴더 규칙 (rules) | 특정 폴더의 파일을 다룰 때만 읽히는 지침. `.claude/rules/` 에 둡니다 |
| 스킬 (skills) | 여러 단계로 된 절차 문서. 설명만 늘 읽히고 본문은 호출될 때 읽힙니다 |
| 권한 설정 (permissions) | 어떤 동작을 묻지 않고 허용할지, 물어볼지, 막을지 정한 설정. 문장으로 부탁하는 것과 달리 프로그램이 강제합니다 |
| 세션 | Claude Code 대화 한 번. 새 세션을 열어야 바뀐 지침이 적용됩니다 |

## 제약

- 행수·크기 한도(200행, 25KB)는 2026년 9월에 확인한 값입니다. Claude Code가 업데이트되면 달라질 수 있어, 지침은 Claude에게 작업 시점의 공식 문서로 다시 확인하라고 시킵니다.
- 검사 도구는 Windows에서 Python 3으로 시험했습니다. 메모리 폴더를 자동으로 못 찾으면 `--memory` 옵션으로 경로를 직접 알려 주면 됩니다.
- 이 절차는 한 사람의 작업 폴더 한 곳에서 실행한 기록입니다. 팀이 함께 쓰는 저장소에 적용할 때는 권한 설정과 삭제 승인을 누가 할지 먼저 정하세요.

## 정리가 끝났다면: naite

prune은 이미 있는 지침을 제자리에 옮기는 도구입니다. 지침에 무엇이 빠져 있는지는 알려 주지 않습니다. 그 일은 naite가 합니다.

- 저장소: https://github.com/aithen-kang/naite
- 하는 일: 비개발자가 AI와 일하며 겪은 실수를 모은 오답노트입니다. Claude에게 이 저장소를 알려 주면, 내 지침 파일을 읽고 거기에 없는 교훈만 골라 제안합니다. 파일을 고치지는 않고 제안만 합니다.
- 쓰는 순서: prune으로 정리를 끝낸 뒤에 쓰세요. 정리 전에 쓰면 naite가 제안한 문장이 또 CLAUDE.md에 쌓입니다. 정리 후에는 제안받은 교훈을 어느 층에 둘지 위의 세 가지 기준으로 바로 정할 수 있습니다.

| | prune | naite |
|---|---|---|
| 묻는 것 | 지침이 제자리에 있나 | 지침에 빠진 것이 있나 |
| 하는 일 | 옮기고 검사한다 (승인받아 실행) | 읽고 제안한다 (실행하지 않음) |
| 쓰는 때 | 지침이 길어졌을 때, 이후 월 1회 검사 | 정리가 끝난 뒤, 새 종류의 일을 시작할 때 |
